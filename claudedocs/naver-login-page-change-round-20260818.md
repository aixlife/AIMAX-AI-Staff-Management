## 1. 무슨 일이 일어났나

네이버가 NID 로그인 화면을 새 구조(`V3_DESKTOP_DEFAULT`)로 개편했다. 로그인 버튼이 바뀌었다.

| | 예전 | 지금 |
|---|---|---|
| 로그인 버튼 | `#log.login`, `.btn_login` | `#loginBtn_column` / `#loginBtn_row` |
| 아이디·비밀번호 칸 | `#id`, `#pw` | 동일 (변경 없음) |
| 그 외 | — | 바로 옆에 패스키 버튼(`#passkeyBtn_*`)이 같은 모양으로 추가 |

2026-08-18 실제 `nid.naver.com` HTML로 확인: 구 선택자 3종 전부 **없음**, 신규 2종 **있음**.

AIMAX 실행기는 아이디·비밀번호까지 채워 넣고 로그인 버튼에서 멈춰
`로그인 버튼을 찾을 수 없습니다`로 실패한다.

### 언제부터인가 — 네이버 점진 배포

같은 실패가 처음 나온 건 6월이다. 네이버가 사용자별로 조금씩 새 화면을 켜온 흔적이다.

## 2. 현주(서이추)는 실패를 "성공"으로 보고하고 있었다

조사 중 별건으로 확인. `app.py`의 원격 잡 처리에서 `hyunju_find`만 워커 결과를 **버리고** 무조건 `done`으로 보고하고 있었다.

```
yeri_write   → 결과 ok=False면 서버에 failed + 사유 전달  (정상)
hyunju_find  → 결과를 읽지 않고 항상 done                  (결함)
```

거기에 `_worker_neighbor` / `_worker_link_neighbor`는 내부에서 **모든 예외를 삼키고** 로그만 남긴다.
즉 네이버 로그인 실패로 터져도 → 예외 삼킴 → 결과 없음 → 서버에 `done`.

실측 근거: 8/17 사용자 오류 보고(`AIMAX-RPT-20260817103127`)에 연결된 현주 잡 3건이 **전부 `done`**.
사용자는 실패를 겪었는데 서버에는 성공으로 남았고, 자동 분류도 붙지 않아 보고가 하루 넘게 `접수됨` 상태로 방치됐다.

이 결함 때문에 **현주 쪽 실제 실패율은 지금 통계로 알 수 없다.** 수정 배포 후 1주일 관찰이 필요하다.

## 3. 수정 내용

### 3-1. 실행기 — 로그인 버튼 탐색 (`auth/naver_login.py`, `constants.py`)

- 신규 선택자 우선, 구 선택자는 뒤에 유지(네이버 A/B 롤백 대비)
- 새 화면은 레이아웃별 버튼 2개를 문서에 함께 두고 하나만 보여준다 → **보이는 것을 고른다**
  (숨은 쪽을 JS로 클릭하면 예외 없이 아무 일도 안 일어나 실패를 조용히 삼킨다)
- 패스키 버튼은 절대 후보에 넣지 않는다(다른 인증 흐름)
- 선택자가 또 바뀌면 로그인 폼 안에서 "로그인" 라벨 버튼을 직접 찾는 폴백 추가

### 3-2. 서버 — 안내 분류 (`oracle/aimax-reports-api/server.js`, `scripts/aimax_report_auto_guidance.py`)

`naver_login_page_changed` 카테고리 신설. `naver_login_required`보다 **앞에서** 걸러낸다.

| | 이전 | 이후 |
|---|---|---|
| 상태 | 사용자 확인 필요 | 확인 중 (운영팀) |
| 안내 | "브라우저에서 네이버 로그인을 완료하세요" | "네이버 로그인 화면 구조가 바뀌어 실행기가 버튼을 못 찾은 상태입니다. AIMAX 수정이 필요합니다" |
| 앱 화면 진단 | 네이버 재로그인 (사용자 조치) | AIMAX 관리자 조치 필요 |
| 자동화 티켓 | naver_editor | naver_editor (동일) |

"다시 해봐도 안 된다"(still_failing) 응답이 와도 사용자 조치 안내로 되돌리지 않도록 막았다.
진짜 2단계 인증·새 기기 등록 건은 그대로 `naver_login_required`로 남는다(회귀 확인 완료).

### 3-3. 실행기 — 현주 결과 보고 (`app.py`)

- `_worker_neighbor` / `_worker_link_neighbor`가 결과 dict(`ok`/`stage`/`error`/`total`)를 반환
- 예외를 삼켜도 `ok=False` + 사유를 남긴다
- 원격 잡은 예리와 같은 판정 경로 사용 — 실패면 서버에 `failed` + 사유 전달
- 이웃 목록 비공개로 후보 0명인 경우도 실패로 보고(예전엔 조용히 성공)
- 중지 요청·완료 팝업 단계 오류는 실패로 잡지 않는다(오탐 방지)
