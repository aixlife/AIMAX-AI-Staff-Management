## 1. 결과 상세 미리보기 — 완료

랜딩 업무 시연을 5종으로 확장(지은 사무 지원 추가)하고, 결과 카드마다 "상세 열기"로 실제 산출물 모양의 샘플 전문을 보여줍니다. 운영실 체험의 완료 업무에서도 같은 상세가 열립니다.

- 직원별 샘플: 예리 블로그 초안(소제목·비교표·CTA) / 송이 경쟁사 브리프 / 현주 잠재고객 목록 / 상수 견적서 / 지은 사무 지원 결과 — 전부 가상 데이터
- 검증: 빌드+테스트 16/16, 뷰포트 3종(1440/1024/390) x 직원 5종 열기·닫기 PASS, 좁은 화면 표는 세로 스택 전환(가로 스크롤 0), Tab/Escape·reduced-motion·기존 스크롤 시연 회귀 PASS, 스크린샷 21장

## 2. 도메인 의견 — aimax.ai.kr 루트 동의

- **현황 실측**: aimax.ai.kr은 이미 오라클 서버(213.35.100.96, Caddy)를 보고 있고, 지금은 `https://makefamily.kr/index.html`로 302 리다이렉트만 걸려 있습니다. 즉 DNS·인증서·서버 전부 준비돼 있어 Caddy 라우트 교체 한 번이면 됩니다. 늘 하던 인프라 그대로라 운영 부담도 없습니다.
- **유의 1건**: 루트를 랜딩으로 바꾸면 makefamily.kr로 가던 기존 리다이렉트가 사라집니다. aimax.ai.kr을 어딘가에 makefamily 링크로 안내해 왔다면 그 경로가 끊기니, 랜딩 푸터에 회사(메이크패밀리) 링크를 넣는 것으로 대체하면 됩니다.
- 검색 대응은 정적 프리렌더 빌드로 해결(현재 hash 라우팅은 공개 전 교체) — 카피 개편 라운드에서 함께 처리.

## 3. 카페24 구매 흐름 — 실측 결과와 최적화 의견

**좋은 소식: 행복 경로는 이미 전자동·거의 실시간입니다.**

**(8/30 저녁 정정·적용 결과)** 처음 조사에서 인입을 "메일 → n8n"으로 보고했으나, 라이브 실측 결과 n8n은 8/8에 폐기됐고(DB 8/7 이후 정지) 실제 인입기는 **mf-order-notifier(mf_ops)가 카페24 Admin API를 60초마다 폴링**하는 방식이었다. 아래 표는 실측 기준으로 정정한 것.

| 단계 | 방식 | 지연 |
|------|------|------|
| 결제 → 서버 인입 | **mf_ops가 카페24 Admin API 60초 폴링** → POST /api/integrations/cafe24/orders (주문번호 dedupe) | 최대 1분 |
| 분류 성공 → 계정+권한+셋업링크 메일 | 자동 (발신 naminsoo@aixlife.co.kr) | 수초 |
| 링크로 비번 설정 → 로그인 | 사용자 셀프 (7일 유효, 3일 미로그인 시 자동 리마인드) | — |

**적용 완료(8/30)**: 1) 실패 자동 재시도 스윕 — server.js 배포·armed 실측(600초·최대 3회·소진 시 1회 알림). 2) 명시 상품 코드 — 실인입기 mf_ops에 이식·라이브(3주기 무오류 실측, 서버 규칙 11코드 사본, 다품목 복수 코드는 안전하게 미전송). 리포의 n8n 패치 스크립트는 죽은 경로용으로 판명 — 매핑 정본 참고용으로만 남김.

수동 개입은 예외 경로 2개뿐이고, 여기가 최적화 대상입니다:

1. **needs_review(상품 분류 모호) 구조적 제거 — 추천, 0원**: 서버는 명시 상품 코드를 받으면 추론 없이 즉시 확정합니다(이미 구현돼 있음). 새 랜딩의 구매 버튼을 직원별 카페24 상품 단일 링크로 만들면 모호 분류로 사람을 기다리는 일이 사라집니다.
2. **failed 자동 재시도 추가 — 추천, 소규모**: 지금은 메일 순단 등 일시 오류도 admin 수동 retry 전용입니다. 10분 간격 재시도 스윕 하나면 됩니다.
3. 메일 파싱 의존 보완(선택): 카페24 메일 템플릿이 바뀌면 인입이 멈춥니다. 서버에 카페24 Admin API 주문 조회가 이미 있어 폴링 백업을 붙일 수 있는데, 1·2보다 급하지 않아 후순위 제안입니다.

## 4. PG 통과 대비 — 준비 설계 (memory 저장 완료)

PG 웹훅 → 기존 주문 수신 엔드포인트로 변환 전달만 하면, 계정 생성·권한·셋업 링크 메일·미로그인 리마인드까지 **현행 자동 파이프라인이 그대로 동작**합니다. 결제 완료 수초 내 메일 도착이 됩니다.

- 새로 만들 것: PG 웹훅 수신부 1개(서명 검증 + payload 변환, 상품 코드 명시, PG 주문번호를 dedupe 키로)
- 재사용: 주문 정규화·자동 처리·계정/권한·셋업 링크·메일·리마인드 전부 (함수 목록은 흐름 지도 문서에 정리)
- 위 3-1(상품 코드 명시)을 지금 해두면 PG 전환 시에도 같은 규격을 씁니다 — 앞단만 갈아끼우는 구조가 완성됩니다
