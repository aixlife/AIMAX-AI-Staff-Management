# 운영실 실전환 패리티 매트릭스 (2026-09-02)

## 결정 박스

- 질문: 리빌드 UI(새 디자인)를 실제 운영실로 전환하는 방식과 1차 범위를 무엇으로 할까요?
- 추천: **점진 전환(A안)** — 새 UI를 실 API에 연결한 "실전환 빌드"를 베타 주소(`/app2`)로 먼저 올리고, 기능군별로 4단계 전환. 기존 `/app`은 전 과정 폴백으로 유지.
- 근거 3: (1) 기존 콘솔은 15,227줄 단일 파일에 24개 API·6탭이 얽혀 있어 빅뱅 교체는 검증 불가 (2) 리빌드 프리뷰는 의도적으로 네트워크 0(계약 테스트로 강제)이라 API 연결 자체가 새 작업 — 화면은 재사용, 데이터 계층만 신설 (3) 로컬 실행기 연동(예리·현주)은 실기기 검증이 필요해 단계 분리가 안전.
- 반대 근거: 베타 기간 동안 두 UI를 병행 운영해야 하고, 서버 정적 파일이 하나 늘어난다.
- 승인 시: Phase 1(로그인+읽기 전용)부터 시작. / 거절 시: B안(빅뱅)·C안(신 UI+구 콘솔 딥링크 하이브리드) 중 택일.

## 두 콘솔의 현재 상태

| | 기존 운영실 (`/app`, app.html) | 리빌드 프리뷰 (apps/aimax-console-preview) |
|---|---|---|
| 상태 | 라이브, 사용자 336명 | 로컬 픽스처(네트워크 호출 0 계약) |
| 구조 | 단일 HTML 15,227줄 | React 19 + Vite, 페이지·컴포넌트 분리, 테스트 61개 |
| 탭 | 대시보드·직원 채용·업무지시·직원 피드백·설정·업데이트 및 오류보고 | 홈·AI 직원·업무·연결 및 설정·도움말 |
| API | 24개 엔드포인트 사용 | 0개 (전부 픽스처) |

## 기능 패리티 매트릭스

| 기능군 | 세부 | 기존 | 리빌드 | 전환 작업 |
|---|---|---|---|---|
| 계정 | 로그인·세션·로그아웃 (`/api/auth/*`) | ○ | × | 로그인 화면+세션 계층 신설 |

| 설정 | 글쓰기 스타일·웹 작업 설정 | ○ | × | 신설 |

| 지원 | 직원 피드백 탭 | ○ | × | 신설 또는 오류 보고에 통합 |

| 기타 | 송이 리서치 모듈 | 제거됨(9/2) | 불필요 | 없음 |

요약: 리빌드는 **화면·폼·문구 품질은 앞서고**, 계정·실행기·서버 연결 계층이 통째로 없다. 전환 작업의 본질은 "픽스처 데이터 계층을 실 API 계층으로 바꿔 끼우기 + 없는 기능군 3개(계정·실행기·피드백) 신설"이다.

## 점진 전환 단계안 (A안)

| Phase | 범위 | 완료 기준 | 예상 라운드 |
|---|---|---|---|
| 1 | 로그인·세션 + 직원 카탈로그·권한 게이트 + 읽기 전용 홈/업무 목록 | `/app2`에서 실계정 로그인 후 내 직원·내 잡이 보인다 | 2~3 |
| 2 | 잡 생성 4종(예리·현주·윤미·상수) + 취소·가드 승인 | 실 잡 생성→진행→결과를 새 UI로 완주, 구 UI와 동일 잡 데이터 | 3~4 |
| 3 | 설정(키 저장·실행기 상태·글쓰기 스타일) + 다운로드 | 예리 hybrid 실기기 흐름 PASS | 2~3 |
| 4 | 오류 보고·피드백 + 세무 폼 + 잔여 정리 | 오류 보고가 기존 자동 안내 파이프라인에 그대로 접수 | 2 |
| 전환 | `/app` 기본을 새 UI로, 구 UI는 `/app-legacy` 폴백 30일 | 전환 후 1주 오류 보고 증가 없음 | 1 + 관찰 |

- 게이트: 각 Phase 끝에서 CEO 확인. 사람 대기(실기기 검증 등)는 별도 표기.
- 리스크: 실행기 연동(Phase 3)이 가장 두꺼움 — 예리·현주는 로컬 실행기+네이버 로그인이 얽혀 있어 실기기 검증 필수. 오류 보고(Phase 4)는 자동 안내·티켓 파이프라인과 필드 계약을 깨면 안 됨.
- 프리뷰의 "네트워크 0" 계약 테스트는 실전환 빌드에서 "허용 API 목록" 계약으로 교체한다(무제한 fetch 허용이 아니라 엔드포인트 화이트리스트).

## 이번 라운드에서 확인 못 한 것

- 기존 콘솔의 세부 동작(가드 승인 UX, 실행기 명령 큐 상세)은 코드 표면만 읽었고 전 흐름을 실행해보지는 않음 — Phase별 구현 시점에 실측.
- 모바일 뷰포트에서 기존 콘솔과 리빌드의 화면 차이는 이번 조사 범위 밖.
