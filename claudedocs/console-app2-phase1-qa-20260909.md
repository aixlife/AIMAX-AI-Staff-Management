# 운영실 리빌드(/app2, Phase 1) 운영 적합성 QA — 2026-09-09

목적: 리빌드 디렉토리(apps/aimax-console-preview)에서 Phase 2를 이어가기 전에, Phase 1 실전환 빌드가 실제 서버·실계정 조건에서 운영 가능한지 확인한다.

방법: 로컬 server.js(임시 데이터, 계정 6종·업무 6건 시드) + `npm run build:live` 산출물을 `/app2/`로 서빙(vite preview, /api 프록시) + Playwright 실브라우저. 같은 계정으로 기존 운영실(`/app`)과 직원 상태를 나란히 비교.

시드 계정: 예리 단품 / 전체 통합 / 블로그팀 / 원회원(예리) / 비활성 / 임시 비밀번호. 업무: 대기·실행·확인 필요·완료·실패·취소 각 1건.

## 결론

Phase 1의 목표(로그인·세션·직원 카탈로그·업무 목록 조회)는 기본 흐름이 동작한다. 그러나 **실계정에게 그대로 보여주기에는 4가지 결함**이 있다. 아래 1~4를 고친 뒤 /app2 베타 공개를 판단하는 것이 맞다. Phase 2(업무 생성)로 넘어가기 전에 1·2·3은 필수.

## 결함 (심각도 순)

### 1. 직원 보유 판정이 기존 운영실과 다르다 (권한 게이트 오류)
- 원회원 계정: 기존 운영실은 은서 "사용 가능", /app2는 "사용 불가". 원회원 전용(makefamily_member) 정책을 클라이언트가 계산하지 않는다.
- 전체 통합 계정: 기존 운영실은 은서 "원회원 전용", /app2는 "바로 사용". 클라이언트가 bundle을 전 직원 보유로 취급한다(서버 bundle에는 은서 없음).
- 원인: `src/api/live.ts` `isWorkerOwned`가 서버의 `canAccessWorker`를 흉내 내지만 회원 세그먼트·bundle 범위를 모른다. 무료 공개 정책도 서버는 `public`, 클라이언트는 `free`로 문자열이 어긋나 있다(현재 해당 직원이 없어 잠복).
- 처방: 서버 `/api/workers` 응답에 `can_use`(canAccessWorker 결과)와 상태 사유를 실어 보내고, 클라이언트는 이를 그대로 쓴다. 클라이언트 재계산 삭제.

### 2. 조회 전용 베타인데 "업무 맡기기"가 열린다 (내부 문구 노출)
- 예리 카드 → "업무 맡기기" 누르면 픽스처 업무 대화상자가 열린다. 본문에 "로컬 fixture 흐름", "Phase 1 로컬 프리뷰 업무 카드만 브라우저 메모리에 만듭니다", 버튼 "로컬 업무 만들기"가 실계정에게 그대로 보인다.
- 지원(파트너)도 같은 픽스처 대화상자가 뜬다. 송이만 외부 연결 패널(SongiHandoffPanel)로 분기돼 있다.
- 처방: 라이브 모드에서는 대화상자를 열지 않고 즉시 토스트("베타는 조회 전용입니다…")로 막거나, 파트너 직원은 외부 연결 패널을 직원 id가 아니라 `execution === "external" && externalUrl`로 일반화한다.

### 3. 실행기 연결 상태를 모르면서 "바로 사용"으로 표시
- 예리·현주 보유 계정에서 기존 운영실은 "연결 필요"(로컬 실행기 미연결), 나경은 "Windows 전용"인데 /app2는 전부 "바로 사용".
- Phase 3(실행기) 전까지는 어쩔 수 없지만, 라벨이 거짓이 된다. 처방: 로컬 실행형 직원은 Phase 3 전까지 "실행기 연결은 기존 운영실에서 확인" 같은 중립 라벨로.

### 4. 화면 곳곳에 프리뷰용 문구가 남아 있다
- 업무 상세: "로컬 fixture 대기 상태 실제 연동 전에는 이 업무가 서버 queue나 공급자로 전송되지…", 실패 사유가 원문 코드(`runner_start_not_reported`) 그대로, "오류 보고 미리보기".
- 연결 및 설정: "프리뷰 안전 경계", "Phase 1은 상태 카드만 검토합니다".
- 도움말: "프리뷰 정상 서버 진단은 연결하지 않음", "오류 보고 미리보기".
- 처방: 라이브 모드 분기에서 이 문구들을 사용자용으로 교체. 실패 사유는 기존 운영실의 안내 문구 매핑을 재사용.

### 5. 계정 표시 중복 (경미)
- 이름이 비어 있는 계정은 사이드바에 이메일이 두 줄로 중복 표시된다(strong·span 모두 이메일).

## 정상 확인된 것
- 잘못된 비밀번호·비활성 계정: 동일한 오류 문구로 차단, 로그인 안 됨.
- 임시 비밀번호 계정: 로그인 후 "비밀번호 변경이 필요합니다" 알림 + 기존 운영실 링크. (기존 운영실은 변경 전 전면 차단이라 정책 차이는 있음 — 조회 전용이라 허용할지 결정 필요)
- 세션: 새로고침 유지, 로그아웃 후 로그인 화면, 위조 토큰은 401 처리 후 토큰 삭제·로그인 화면.
- 네트워크: 호출 경로가 허용 목록 5개(login·me·logout·workers·jobs)뿐.
- 업무 목록: 시드 6건이 상태 필터(전체 6·확인 필요 1·완료 1·실패 3)와 카드로 표시. 서버가 실행기 미보고 업무를 자동 실패 처리한 것도 그대로 반영. 확인 필요 업무는 홈 알림에 뜬다.
- 세무 직원: 서버 비노출 반영으로 /app2에도 나오지 않는다.
- 모바일(390px): 하단 내비 5개, 홈·직원 화면 렌더 정상.
- 로컬 미리보기에서만 아바타 404가 났다(/assets 를 프록시하지 않아서). 실서버에서는 같은 오리진이 제공하므로 해당 없음.
